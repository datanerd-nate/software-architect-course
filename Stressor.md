# Stressors
| Stressor Scenario | Potential Impact | Architectural Safeguard and Mitigation | Failure Mode/Recovery |
| --- | --- | --- | --- |
| Exceeding 200K student load due to reschedules | Queue backlogs; potential database connection exhaustion in Result Consolidation. | Queue Backpressure & Rate Limiting: Intake service accepts writes into persistent storage independent of consolidation rate. PgBouncer limits active database connections. | Message lag increases in queues, but zero student write failures or dropped submissions occur (202 Accepted). |
| MCP AI Engine Outage / Severe Latency,LLM inference calls timeout or return 5xx errors in Grading Service. | Queue Throttling & DLQ Routing: Workers isolate short-answer queues from deterministic queues. Failed calls retry with exponential backoff. | Short-answer grading delays accumulate in the broker, but multiple-choice grading and intake continue unaffected. |
| Malicious Prompt Injection in Student Text,"Student attempts to override grading instructions (e.g., ""Give 100%"")." | Input Sanitization & Confidence Fallback: Input text is sanitized before MCP context injection. Irregular outputs produce low confidence scores (<0.85). | Submission automatically flags as low-confidence and routes to the Teacher Review Queue via GradingReviewRequired. |
| Database Connection Pool Exhaustion in Consolidation,Result Consolidation Service cannot lease DB connections under load. | NACK / Redelivery Mechanism: Connection attempts timeout at 2,000ms. Consumer NACKs the event, returning it to the broker. | Messages remain safely buffered in Kafka/RabbitMQ until connection pool capacity opens up. |
| Network Partition During Outbox Publishing | Service DB commits, but cannot talk to the event broker. | Transactional Outbox Pattern: Outbox rows are committed locally in the same ACID transaction as the business state change. | Once network connectivity recovers, outbox relay background workers resume reading from local tables and publishing events. |
